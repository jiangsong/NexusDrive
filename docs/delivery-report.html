发现并修复的缺陷

这四个都不是编译错误，是行为错误。它们在单元测试全绿之后才暴露出来，说明只测组件不测系统会漏掉什么。

01

提交发生在 RELEASE 里，而内核不等待 RELEASE

写完文件后立刻读，读到的是空的。原因是数据提交挂在 FUSE 的 RELEASE 上，但内核对 close(2) 只等待 FLUSH 的回复，RELEASE 是异步的。

提交移到 FLUSH。close() 返回时数据已经在本地日志里。

发现于 真实挂载下的读写测试
02

FLUSH 会来多次，第一次就把文件关了

修好上一条之后，shell 的 echo > file 报 I/O 错误。内核为每个关闭的文件描述符发一次 FLUSH，包括 dup 出来的；CREATE 之后就先来了一次，把 staging 文件关掉了，后续写入全部失败。

FLUSH 改为提交但保持句柄可写，RELEASE 才做拆除。同一句柄的连续提交会互相取代，不会为一个文件排队两次上传。

发现于 CLI 挂载冒烟测试，仅在真实内核路径上出现
03

尚未上传的文件无法重命名

编辑器保存文件的标准做法是写临时文件再改名覆盖。因为临时文件还在上传队列里、远端还没有它的 ID，改名会拿一个假 ID 去问服务端，返回"文件不存在"。

改名和删除现在会识别这种状态：直接改写队列里那条待上传记录的目标，或者取消它，不去打扰服务端。

发现于 模拟编辑器保存的冒烟测试
04

本地连续两次写同一文件，第二次被误判为冲突

冲突检测比对的是"打开时看到的版本"。但第一次写入后，本地版本已经变成一个待上传的临时标记，第二次写入拿它去比对远端，永远不相等，于是把自己的修改存成了冲突副本。

元数据里分开记录"当前版本"和"最后已知的远端版本"，冲突检测只看后者。冲突的定义回到它本来的意思：别人改了。

发现于 混沌测试的并发写场景
05

重命名不覆盖目标

rename(2) 的语义是替换目标文件，但服务端路径没有先删除已存在的目标，网盘拒绝覆盖后返回"文件已存在"。编辑器第二次保存同一个文件就会失败。

覆盖的决定移到 VFS 层：驱动继续拒绝静默覆盖，由上层显式删除目标再改名。网盘做不到原子替换，所以失败时保留的一定是源文件，用户想留下的内容不会丢。

发现于 重复运行冒烟测试
06

重试时间是秒精度，亚秒延迟被抹平

上传队列把下次重试时刻存成 Unix 秒。任何小于一秒的退避或合并窗口都会被四舍五入成"立即可取"，于是退避形同虚设，一次 shell 重定向也会发出两次真实上传。

改成毫秒精度并带上迁移。同时加了一个默认两秒的写入合并窗口：数据早已在本地持久化，只是推迟网络发送，在限速网盘上这能省掉一半请求。

发现于 间歇性失败的回归测试
07

两个驱动会把错误的字节当成正确数据

115 与夸克的分块读同时接受 206 和 200 两种响应，但没有处理 200 的情况。如果 CDN 节点忽略了 Range 头返回整个文件，驱动会把从偏移 0 开始的字节当作请求的窗口交出去，直接写进块缓存。这是静默的数据损坏，不是可见的失败。

把这段补偿逻辑提炼成共享函数，所有驱动统一走它，并加了一个模拟"忽略 Range 的服务器"的测试。

发现于 驱动一致性审查
08

残缺的分片被当作上传成功

百度与 123 的分片上传忽略了实际拷贝的字节数。源如果提前结束，会上传一个短分片并报告成功，最终合成一个被截断但看起来正常的文件。阿里则把 409 当成功，可能返回空的分片标识。

三处都改为显式核对字节数与标识，不符就失败，交给重试或死信处理。

发现于 驱动一致性审查
09

部分路径返回没有版本号的条目

块缓存用（网盘、文件 ID、版本号）做键。夸克的上传完成与天翼的提交在拿不到哈希时会返回空版本号，两份不同的内容就会共用一个缓存键，远端改动后可能读到旧文件的字节。

加了统一的版本号回退：优先用内容哈希，否则用大小加修改时间的指纹，目录用其 ID。所有手工构造的条目都过这一道。

发现于 驱动一致性审查
九个缺陷都被固化成了回归测试。前四个来自真实挂载与混沌测试，第 5、6 个来自重复运行发现的间歇失败，后三个来自对两组独立编写的驱动做的一致性审查。

能力矩阵是唯一的决策依据，上层从不按名字区分网盘。声明支持秒传就会先算哈希，声明支持服务端移动才会用它，声明直链可外传才会交给 MCP 的调用方。

MCP 接口

MCP 服务直连 VFS 核心，不经过内核，所以没有挂载也能用。这在容器里或没有 FUSE 权限时很有用。

约束做法
响应不撑爆上下文每个工具都有分页游标与字节上限，截断时返回续读位置
路径不越界允许列表先规范化再校验，.. 穿越无效
删除不误伤必须显式传 confirm=true，因为删除同时作用于远端
大文件不走服务get_download_url 返回直链与必需的请求头
内容搜索不假装只搜已缓存的文件，跳过的部分会明说并建议先 pin
凭据不外泄token 与 cookie 永不出现在任何返回里
 
cloudfs mcp install --client claude   # 打印 .mcp.json 片段
cloudfs mcp install --client codex    # 打印 config.toml 片段
