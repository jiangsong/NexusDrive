## 问题清单

### E2E-001（P1，已修复）导出进度仍按 5 秒轮询，无法满足 1 秒实时进度目标

复现：

1. 打开“导出”，创建一个作业。
2. 作业行显示“规划中”。
3. 等待约 2 秒，页面没有主动反映已经完成的后端状态。
4. 点击“刷新”后立刻显示“已完成”。

代码证据：`internal/control/web/screens/exports.js` 末尾仍使用 `setInterval(..., 5000)`；全局 SSE 客户端只处理 `status` 和 `change`，没有 `export` 事件处理。

影响：短任务状态明显滞后；长任务的速率、ETA 和暂停原因最多延迟 5 秒，未达到“活动进度延迟不超过 1 秒”的验收条件。

建议：在 `/events` 推送 `export` 事件，由导出页订阅并局部更新对应作业；仅将轮询保留为 SSE 断线后的降级路径。

修复与回归：后端 `/events` 已每秒发送 `export` 快照，前端订阅后局部更新作业列表并移除导出页 5 秒定时器。浏览器新建空目录导出后未点击“刷新”，约 1 秒内自动显示“已完成”。

### E2E-002（P1，已修复）导出页没有作业详情和文件级分页入口

复现：

1. 打开已完成的导出作业列表。
2. 作业行只有“丢弃记录”操作，作业行不可展开，也没有详情按钮。
3. 无法从 UI 查看 item 列表、单文件失败原因、重试原因或成员吞吐。

影响：即使后端已提供 `/exports/{id}/items?cursor=&limit=&state=`，用户仍无法在控制台诊断大作业和失败文件；百万 item 分页能力无法通过产品 UI 使用。

建议：增加作业详情抽屉，接入 cursor 分页与 state 筛选，并展示失败原因、重试状态、成员吞吐和 ETA。

修复与回归：作业行新增“详情”，抽屉接入 `/exports/{id}/items` 的 cursor、limit 和 state，展示路径、大小、状态、尝试次数、最后错误、成员吞吐及 ETA。浏览器验证详情打开、状态筛选和空结果状态正常。

### E2E-003（P2，已修复）复制/导出表单校验失败会关闭弹窗并丢失输入上下文

复现：

1. 打开“新建复制”或“新建导出”。
2. 不填写必填路径，点击“开始”。
3. 弹窗立即关闭，只在主页面底部显示错误 toast。
4. 用户必须重新打开弹窗；若只是漏填一个字段，已填写的其它字段也会丢失。

代码原因：共享 `openForm` 在确认按钮点击时先执行 `close(true)`；复制和导出在弹窗关闭后才校验路径（`copies.js` 与 `exports.js`）。

建议：为 `openForm` 支持提交回调或表单级 validator；校验失败时保持弹窗、保留值、给无效字段显示内联错误并聚焦首个错误。

修复与回归：共享表单支持提交前 validator。复制和导出缺少路径时均保持弹窗，显示内联错误并聚焦首个无效字段；浏览器分别验证通过。

### E2E-004（P2，已修复）共享表单标签未与控件建立语义关联

复现：检查“新建导出”的可访问树：两个复选框没有 accessible name；文本框名称来自示例 placeholder，而不是“来源”“目标目录”标签。存储池创建页的名称和副本数输入也没有可访问名称。

代码原因：`openForm` 用普通 `div` 渲染 label 文本，没有 `<label for>` 或 `aria-labelledby`；多个独立创建表单也使用相同结构。

影响：屏幕阅读器无法可靠说明字段含义；按 label 定位的自动化测试不稳定。

建议：让共享表单生成唯一 id，并使用 `<label for>`；复选框用包裹式 `<label>` 或 `aria-labelledby`。补充 axe/ARIA 自动化门禁。

修复与回归：共享表单为控件生成稳定唯一 id，并用 `<label for>` 关联；独立的存储池表单同步改用语义标签。Chrome 可访问树已能以“来源”“目标目录”“校验文件内容”“镜像模式”等名称识别控件。

### E2E-005（P2，已修复）导出创建仍依赖手工输入路径

复现：“新建导出”仅提供来源文本框和本机目标路径文本框，没有 VFS 树形选择器或桌面原生目录选择按钮。

影响：路径容易输错，用户无法发现可选来源；桌面壳没有提供计划中的原生目录选择体验。

建议：来源接入 VFS 树；桌面模式调用目录选择桥接，浏览器模式保留手工输入并显示服务端校验结果。

修复与回归：来源字段新增 VFS 树选择器，支持进入目录、返回上级、选择当前目录或文件；桌面壳绑定原生目录选择函数，浏览器模式保留手工输入并明确提示。浏览器选择 VFS 根目录后字段正确回填 `/`。

### E2E-006（P2，已修复）存储池控制台只能创建基础池，配置闭环缺失

复现：当前无池页面只提供名称、成员和副本数；没有成员 class、failure domain、write mode、min replicas、超时、rebalance 策略、placement preview，也没有明确的即时生效/`restart_required` 标记。

影响：高级放置和故障域能力只能依赖配置文件或其它接口，保存前无法预览候选与排除原因。

建议：补齐策略编辑和 placement preview，并在所有配置响应和 UI 状态中明确显示是否需要重启。

修复与回归：创建和编辑界面已覆盖成员 class、failure domain、write mode、min replicas、超时、repair concurrency、规则及 rebalance 策略；新增 placement preview 展示候选、排除原因和预计分布，配置响应携带 `restart_required`。浏览器可访问树和 HTTP 集成测试均验证通过。

### E2E-007（P1，已修复）Quark 新增连接后要求用户复制终端命令

原行为在新增 Quark 后显示 `cloudfs config auth ...`，普通用户还需要进入开发者工具获取 Cookie，成本过高且容易泄露会话。

修复后由守护进程按夸克网页当前扫码流程获取 token、轮询确认、用一次性 service ticket 换取 Cookie，并直接写入 CloudFS 密钥存储。控制台只拿到随机授权会话 ID，并通过同源、`no-store` 的 PNG 接口显示二维码；QR token、service ticket 和 Cookie 均不进入页面文本或配置文件。已有但未授权的 Quark 连接也可从连接设置中点击“开始授权”，中断时会取消后台轮询。

### E2E-008（P1，已修复）Quark 扫码成功后页面仍显示“未授权”

真实扫码后凭据已经写入密钥存储，配置文件也已经保存凭据引用，但授权完成协程没有重新发布控制面的内存配置。随后页面立即重新请求账号详情时仍读到启动时的旧视图，错误显示 `has_credentials=false`，造成绑定失败的假象。

修复后授权协程先重新加载并发布配置，再将会话标记为 `done`，保证完成状态与账号详情之间具有正确顺序；异步失败同时写入经过脱敏的服务端日志。回归覆盖“授权流程修改磁盘配置 → 状态变为 done → Collector 已发布新配置”的完整顺序。现有扫码结果无需重扫，重载 9202 后显示“已授权”，并通过真实账号根目录只读连通检查。
