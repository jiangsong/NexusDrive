# 缓存固定与在线管理

## 命令

`pin <虚拟路径>`、`unpin <虚拟路径>`、`warm <虚拟路径> [深度]`、
`cache stats|gc|pins` 支持 `--config`、`--json`、`--timeout`（默认 30 分钟）。
路径是挂载内部路径，例如 `/work`，不是宿主机的 `/mnt/cloud/work`。
warm 默认递归全部目录，深度 0 只列当前目录。

命令优先连接 Unix 控制 socket，再尝试配置的回环 TCP 端点。仅在尚未发送请求且端点
明确不存在/拒绝连接时允许离线处理；请求发出后响应丢失不会重放。离线操作先取得 journal
所有权，再打开缓存；不恢复上传队列、不启动上传器、目录预取器或远端增量轮询。
离线命令目前仍需要可构建的 provider 配置；完全只读、不依赖账号的离线缓存清单待补。

控制接口为 `GET /cache/stats`、`GET /cache/pins` 与
`POST /cache/pin|unpin|warm|gc`。POST 使用 JSON，路径字段为 `path`，warm 另有 `depth`。
要求 `X-CloudFS-Control: 1`，拒绝浏览器 Origin 与非本地主机名。MCP 同时提供 pin/unpin，
沿用工具服务的路径允许列表；固定缓存不修改远端文件，因此不受远端只读模式禁止。

## 预算（上限与磁盘留白）

`cache.max_size` 是缓存占用上限（0 = 无上限），`cache.min_free` 是缓存所在文件系统至少
保留的空闲空间（默认 5 GiB，0 = 不留）。写入先落本地 staging，可用空间低于 `min_free`
时 `write()` 直接返回 `ENOSPC`，而不是把系统盘写满——控制台 `#/storage` 的"可用磁盘"卡片
在这时变红并说明原因。两个值可在同一页"调整预算"里改：`GET/PUT /cache/config`
（JSON 字段 `max_bytes`、`min_free`，字节数）先写进配置文件（保留其余 YAML 不动），再经
`cache.SetBudget` 对运行中的守护进程立刻生效；返回的 `applied` 说明是否已生效。状态文档
`cache.max_bytes`/`cache.min_free` 报告的是运行中的值，不是启动时的配置。（2026-09-20）

## 固定规则

- 文件规则精确匹配路径，目录规则递归匹配子树；`/work` 不会误匹配 `/workshop`。
- 多条规则共同生效。移除目录规则不会移除独立的子文件规则；移除子文件规则也不会绕过
  仍存在的父目录规则。`cache pins` 可查看规则来源。
- 规则跟随路径，不跟随 inode。把文件移出固定子树后释放该身份的用户固定；旧路径规则
  仍保留，可在文件不存在或远端不可用时解除。不会自动删除用户的固定意图。
- 同一个远端文件映射到多个路径时，只要任一已缓存的路径被固定，共享缓存就保留。
- 挂载布局中的 `pin: true` 是配置规则，必须修改配置并重启，不接受命令静默覆盖。
- 用户固定与保护未上传数据的临时 pin 独立。unpin 不会使尚未上传的本地数据可被淘汰。
- **对账的代价属于固定集合，不属于缓存大小**（2026-09-06）。树变化（改名、删除）之后要重新
  判定哪些缓存身份仍被保留，做法是问"规则覆盖了什么"——每条规则一次向下递归查询
  （`meta.SubtreeRefs`），再与当前带用户固定的键（`cache.UserPinnedKeys()`，纯内存）比对。
  反过来问"每个缓存对象在哪、被固定了吗"会退化成每个缓存对象一次元数据查询，而这段逻辑
  在**每次改名和每次删除**上都跑。规则路径只用本地元数据解析，断网也能恢复。
  规则覆盖但尚未取过内容的文件不会在这里建缓存记录，它们在第一块入缓存时才被标记。

## 下载、恢复与失败

先保存规则，再下载。每个文件在第一块下载前进入防淘汰状态；因此缓存不足时明确失败，
不会通过淘汰此前下载的块维持一个虚假的“下载完成”。成功返回前等待该文件的缓存后台
写入结束并检查完整性。这里承诺缓存写入完成，不等同于 journal 的掉电持久性承诺。

下载取消、空间不足、网络或磁盘失败会保留规则及已经取得的块。再次 pin 可补缺块，或
使用 unpin 放弃固定。运行中的 daemon 在 journal 恢复后开始补齐持久化规则；一分钟
检查一次，并在目录变化时唤醒，仍遵循目录 TTL、增量刷新、代理和限流。未完成状态会
通过 status 警告暴露；不会把后台失败当成成功同步。解除规则后停止继续下载后续块，
已经在途的调用可能完成。

启动恢复已有缓存的防淘汰标记不需要联网。文件内容被远端替换后，后台按新版本补齐；
pin 是缓存策略，不是历史备份，不阻止正常的远端删除/版本失效处理，也不保证远端变化
被立即发现。

## 内容预算与回收

`cache.max_size` 已统一约束块与完整文件；完整文件按 inode 去重，同一文件的多条
硬链接只计一次。`max_age` 和 GC 同样处理未固定的完整文件。打开的完整文件由
`OpenWhole` 租约保护，失效/原子替换后仍被旧读者持有的 inode 继续计量，直到最后
一个租约关闭。hydrate 转换期间两份内容同时存在，需要额外空间；不足时保留原块并
返回错误，不在转换后把完整文件从计量中隐藏。

计量是内容字节，并非 `du` 的物理分配总量：数据库、身份标记和文件系统元数据不在
内容额度内。重启识别出的遗留临时文件、写入结束后未能删除的临时文件会计量并由 GC
重试清理；不会按通配符删除当前正在生成的临时文件或不认识的文件。

`cache stats` / status / metrics 提供以下信息：

- `Bytes`：块、去重完整文件和遗留临时内容的合计；包含仍被租约持有的旧 inode。
- `WholeBytes`、`LeasedBytes`、`OrphanBytes`：完整文件、带打开租约的完整文件、遗留临时内容；均是上述合计的子集，不能重复相加。
- `ReservedBytes`：hydrate 临时副本及淘汰后仍在写盘的后台副本预留。
- `WriteReservedBytes`：正在执行的 journal 写入预留，不属于缓存内容额度。

已提交 journal 内容的零分配硬链接允许超过 `max_size`：拒绝登记会让已确认的本地
写入在 VFS 中不可读。超额仍如实计量，并阻止新增缓存内容；待上传数据不会为了
回收空间而丢弃。`max_size` 因而不是 journal 配额或整个缓存目录的硬磁盘配额。

## 写入空间背压

daemon 将 journal 与缓存接到同一空间准入器。staging 每次写入和 truncate 扩容前
检查目标目录所在文件系统的可用空间，并扣除并发日志写入、待落盘缓存及 hydrate
预留；不足时先尝试淘汰可回收缓存，仍不足返回 `ENOSPC`。固定内容、打开租约和
待上传数据不因此被删除。写入结束后释放预留，无论成功还是失败。

覆盖写也按写入字节申请空间，避免稀疏空洞和写时复制绕过检查；truncate 扩容按逻辑
增长量申请，属于保守策略。已有 staging 的缩小/清空仍允许进行。空间检查失败时拒绝
写入，不把未知容量当作无限容量。底层部分写入后报错时，已接受的字节仍更新长度和
哈希；FUSE 保留 `ENOSPC`，不再误报为 `EIO`。

这是应用层准入，不是文件系统强制预留：其他进程、元数据开销及文件系统分配粒度
仍可能消耗空间。不能保证全盘剩余量绝不跌破 `min_free`。独立使用 journal 包而未
配置空间回调时，仅有文件系统自身的容量限制。
