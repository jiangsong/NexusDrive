# 复制准备日志：恢复路径与验收边界

本模块已接入 VFS Copy、CLI/MCP/控制面的复制调用，以及 daemon 的后台恢复。
已有 VFS Copy 下载中途强杀测试，以及现场编译生产二进制 `cp` 中途强杀后由独立
生产 MCP-only daemon 进程续跑的测试；真实账号及物理掉电仍未验收，不能据此宣称
整个 Copy 模块完成。

## 已实现

Journal schema v7 的 `copy_jobs` 保存复制意图：源路径、remote、对象 ID、版本、长度，
目标路径、remote、父对象 ID、模式及所需哈希；当前 CopySpec JSON 还保存两端账号
代次。不得存储临时下载链接或凭据。
payload 放在 journal 私有 `copies/<UUID>.part` 中，普通 `staging/` 的恢复清理不变。

| 状态 | 内容所有者 | 可执行操作 |
|---|---|---|
| preparing | Copy 作业 | 顺序追加、保存检查点、关闭后恢复 |
| ready | Copy 作业 | 只读保留、原子交接上传 |
| submitted | 对应 Upload 行 | 上传器处理；不能再次恢复为下载或再次入队 |
| failed | Copy 作业 | 保留内容待检查，不自动继续 |
| cancelled | Copy 作业 | 显式取消并保留内容，仅显式重试可重新排队 |
| purging | 独立的 copy_cleanup 意图 | 已确认清理，无下载/交接；故障可继续清理 |

- `BeginCopy` 在返回前保存意图。同 remote/父对象 ID/目标文件名的活动准备只能有一份，
  同一个作业在单个 journal owner 中只能有一个准备句柄；只读或非 owner 不能准备。
- `BeginCopyFromWhole` 复用不可变完整缓存 inode，链接和校验完成后直接持久化 ready
  作业，绝不先把共享 inode 登记为可截断的 preparing 文件。恢复后仍不可写/截断，
  释放作业或上传的私有链接不删除源缓存。payload 使用绝对路径，可跨相对/绝对目录
  配置方式重开同一个 journal。
- `Write` 只允许顺序追加且不能超过源长度，使用共享空间准入器。`Checkpoint` 在
  power 模式先同步 payload、copies 目录及其父目录，再提交偏移和 CRC32C。同步或
  数据库失败不会推进可恢复偏移；crash 模式不做额外 fsync，恢复仍校验内容。
- `ResumeCopy` 验证文件类型、inode 与已确认前缀 CRC32C，只有校验通过后才截掉
  未确认尾部。截短、校验失败或符号链接均拒绝，不删除内容。恢复时一次重建流式
  哈希状态，之后检查点不反复重读整个已下载前缀。
- `Submit` 在一个 SQLite 事务中创建固定 ID 的上传行并将作业置 submitted；事务
  失败两边都不生效。不能覆盖已有上传 ID，重复提交和向其他目标交接被拒绝。
  VFS 提供绑定的目标 inode 与 `needs_publish` 标记，复用已有本地发布恢复。
- 启动回收保留准备中、完整及失败作业的 payload；submitted 由上传行负责保留。
  上传删除也检查未交接作业的内容所有权。只删除私有目录中确定没有所有者的条目，
  不跟随符号链接删除其目标。
- `Close` 释放句柄，不代表取消，也不会隐式提交。`FailCopy` 必须先关闭句柄，保留
  失败数据并释放目标准备预约；不能撤销已经交接给上传器的任务，也不能改变 cancelled。
- `CancelCopy` 可取消仍打开的准备句柄：持久化 cancelled，Checkpoint/Submit 的 SQL
  状态门禁阻止继续交接；VFS 同时取消当前下载 context。已 submitted 时明确拒绝。
- `RetryCopy` 对 failed/cancelled 先验证前缀并截掉未确认尾部，再恢复 preparing/ready。
  完整 payload 保持不可变；目标预约仍唯一。每次取消推进 revision，重试以原 revision
  条件更新，因此较早的重试不能撤销新的取消请求，包括对 cancelled 作业再次取消。
- v5 表在一个事务中重建以扩展状态约束，保留原记录，新增 revision 默认 0。也覆盖
  旧迁移留下准备表但尚未更新 schema 标记的情况。非 owner 不执行迁移。
- v7 增加独立 `copy_cleanup` 表，显式清理在同一事务中移走终止准备记录并保留完整意图；
  查询合并两表呈现 purging，旧版只读日志不要求此表。删除私有 payload 后再移除意图，
  失败可重试，启动 GC 不抢先删除仍属清理意图的内容。上传插入不能引用正在清理或已
  移除作业的私有 payload；清理也会检查所有上传引用及活动准备句柄。

## VFS 与 daemon 接线

- 普通复制使用 `BeginCopy`，每 1 MiB 保存检查点；完整缓存通过持有租约的
  `BeginCopyFromWhole` 复用。只有明确不支持链接或链接身份变化时才选择流式准备。
- 作业记录源/目标挂载前缀、根对象和账号代次，以及目标父 inode 与元数据库身份。
  重开原库保持身份，新建元数据库生成不同身份，防止把重新分配的 inode 当成旧目标。
  恢复远端源时先在任何 provider IO 前核对源账号绑定，再检查对象 ID、非空版本、
  长度和类型，并按原版本仅下载剩余字节；ready 作业无需再访问源，但发布仍核对目标账号。
- 元数据库 schema v6 的 `copy_bindings` 与完整目标节点在同一 FULL 事务中落地，
  缓存链接先于节点发布。绑定在删除后仍保留，不能因恢复而重新创建已删除目标。
  此绑定事务在 crash 模式下也使用 FULL；新增同步开销尚待性能测量。
- 目标创建至上传交接期间，VFS 写打开和改名返回忙，不能插入比复制更新的写入；
  本地删除取消准备作业。发现独立改动后的绑定拒绝恢复，仍被元数据引用的缓存不清除。
- daemon 启动及每分钟扫描准备作业；前台句柄独占作业，不会重复下载。关闭会取消后台
  IO、保留检查点并等待退出。`NoBackground` 的离线管理栈不自动续跑。
- 前台复制返回准备错误或取消时，将作业标记 failed 并保留内容；进程强杀则留下可恢复
  的 preparing/ready 作业。后台临时失败保留检查点，源/目标变更等错误转 failed，
  通过 status 警告暴露。failed 作业不会自动重试。
- 显式管理取消使用 cancelled，不被前台错误清理改回 failed。重试在排队前预检查
  元数据库绑定/同名目标，发布时仍进行原子检查。后台收到显式重试后立即唤醒。
- ready/failed/cancelled 作业如仍被当前元数据引用为完整本地版本，启动校验 payload
  后重建缓存链接及临时 pin；不创建缺失 inode，不启动被取消的下载或上传。
- `ForgetCopy` 在原元数据库确认无本地引用后，用 schema v7 的真实 FULL 屏障事务
  同步删除，再开始清理。缓存删除失败会保留意图与 journal payload，不误报成功；
  绑定墓碑保留，打开租约继续可读且计量。后台只继续已确认的 purging，不自动清理
  其他失败/取消作业。CLI/HTTP 的显式确认和使用边界见 [复制命令](copy.md)。

## 仍需完成

1. CLI/控制面已有列表、单条查询、分页、准备任务重试/取消，以及无引用内容和记录的
   显式 forget；MCP 同样已有受源/目标双路径、挂载及数据库身份限制的管理工具。
   已交接上传可通过 `uploads cancel <upload_id>` 请求停止并保留内容，不回滚远端
   效果；现可用 `uploads resume <id> --confirm` 校验后发起新尝试，并保留旧会话历史，
   不代表自动对账。取消后的回收、完整远端终态历史仍缺。在线上传 drop 已使用
   VFS 本地清理协调器，仍不能仅靠删除日志或手工改数据库处理。
2. 准备目标改名的完整恢复语义，目前交接前明确返回忙；跨客户端同名创建的原子
   不覆盖契约仍缺失，本地绑定不能替代服务端条件创建。
3. 真实账号、物理掉电、长时间磁盘故障和大文件检查点性能验证。生产 CLI 强杀
   恢复已通过两个 HTTP WebDAV 模拟服务验收，不等于这些外部环境验证。

当前回归已覆盖 VFS 下载/绑定后强杀、只补剩余字节、唯一上传交接、绑定删除不复活、
源版本变化、挂载/元数据库/源目标账号代次变化、只读/取消拒绝，以及 daemon 离线不恢复、后台
恢复后完成上传。存储层另有同步失败、空间拒绝、前缀损坏和未确认尾部截断测试。
生产进程测试不使用 VFS 故障钩子或测试专用驱动：在源服务器的第二段 Range 请求
阻塞时强杀 `cp`，独立启动生产 daemon，验证仅补剩余字节且目标收到一次完整 PUT。

服务端 Copy 的未知结果对账仍是独立工作，不能自动用普通上传重放一个可能已生效的操作。
