# 目录分页与冷刷新

## 当前实现

缓存分页由 `Meta.ChildrenPage` 和 `VFS.ReadDirPagePath` 提供，按父 inode、名称索引
定位。MCP 工具按名称续页，资源按最多 128 项窗口输出。目录内容在两次请求之间
可以变化，游标不是一致性快照；新建在游标之前的项需要从头再扫。

首次读取或 TTL 过期时，VFS 将 provider 的各页转换为最多 200 项的批次，写入独立
SQLite 连接的 TEMP 表。不会把所有 provider 页、全部旧节点或全部变更名称攒成
一个 Go 切片/映射。旧节点仅按当前批次查询；删除子树的 inode 集合也在 TEMP 表中
计算。每个 Store 最多保留 8 个暂存连接；等待网盘期间不占普通元数据连接池或写锁。

支持 `Caps.StreamList` / `StreamLister` 的驱动直接逐条送入同一个 200 项收集器；
没有该能力时沿用 provider 分页及 TEMP 游标去重。流式路径只有在未交付任何条目
且明确返回 ErrUnsupported 时才能回退；已交付前缀、回调失败或取消都不能重放。
即使驱动错误地忽略回调错误，也不确认完整目录。统计包装保留该能力，仍计为 list
操作；流式 list 的耗时包含下游暂存等待，并非纯网络耗时。

WebDAV/OpenList 已走 HTTP 流式 PROPFIND，逐个 DAV:response 解码，不再先聚合
整个响应字节和 multistatus 数组。条目及忽略的扩展元素有 1 MiB 读取预算，另有
解析器缓冲和结构开销；没有整目录条目数量上限。检查完整 XML 收尾，拒绝截断、
错误根/命名空间、额外文档、超大元素及不可验证的成员（属性全失败、缺 href、
不属于 Depth:1 的直接子项、负长度），避免错误地把部分结果当成完整目录。
回调失败/取消关闭响应体，不重试已开始交付的响应。资源 href 先解析 URL 再取
已解码路径，保留编码的 #、?、字面 %2F，并检查配置根路径边界。
PROPFIND 的多状态响应结构依据 [RFC 4918 §9.1](https://www.rfc-editor.org/rfc/rfc4918.html#section-9.1)。

TEMP 配置为 FILE，缓存建议值为 2 MiB，并允许 cache spill；强制 TEMP_STORE=3
的 SQLite 构建会被拒绝。TEMP 数据属于连接，关闭连接时由 SQLite 清理，而非
可恢复的下载任务。[SQLite 临时数据库说明](https://www.sqlite.org/tempfiles.html#temp_databases)

## 发布与失败边界

- 元数据库 schema v9 增加目录刷新代次。新开始的刷新会阻止更早的在途结果发布，
  包括通过另一 Store/进程启动的刷新。数据库身份、目录 inode、remote/远端目录 ID
  必须仍匹配。普通上传的本地账号/元数据库围栏已由 journal v11 独立实现。
- 删除和改名会在同一元数据事务内更新相关父目录的刷新代次，跨目录移动同时
  更新源/目标目录，防止已完成的删除或改名被旧列表撤销。显式目录失效、全局
  缓存失效及传统 PutDir 合并也会使相关旧列表失效。事务失败时一起回滚；同名
  同位置改名及无关目录的操作不会使当前目录刷新失效。
- 各页暂存时不修改可见子项、目录完整标记或刷新时间。重复名称、非法名称、重复
  游标、存储错误和取消使本次暂存失效，不能将前半份列表作为完整目录提交。
- 最后一次写事务合并全部暂存结果、搜索索引、删除集合与目录刷新时间。事务中
  按当前元数据判断保护条件，保留本地待上传/正在写入和刷新期间新建的内容。
- 删除目录前还检查后代是否需要保留，防止远端漏掉父目录时，连带清掉尚未上传
  文件的本地元数据。这只保留本地可读内容，不会自动重建已删除的远端父目录。
- 同名目录的远端对象 ID/remote 改变，或文件与目录类型互换时，旧子树、目录
  完整状态和名称索引属于旧对象，不能继承给新对象。没有受保护内容时，在同一
  事务中删除旧子树并分配新 inode；存在受保护后代时保留整个旧目录及原远端 ID，
  不把尚未上传的内容静默绑定到新目录。仅目录版本改变不自动替换 inode/子树。
- 中途失败或进程被杀后，不自动续用半份暂存；下一次重新列举。已有完整缓存时
  继续沿用 VFS 的“刷新失败则返回旧列表”策略，刷新时间不会因失败而前移。
- 发布返回错误时，也保守发送失效提示，因为部分底层提交错误的结果可能不确定。
  不把“调用返回错误”推断为所有持久化效果都必然未发生。

## 增量事件和活动写句柄

delta 删除和更新使用 `Meta.ApplyRemoteNode`，在同一写事务中重新读取原节点、
检查快照及 VFS 的保护条件，再删除/更新/替换。目标已消失时不重建；节点已被
其他本地操作修改时拒绝旧快照，PollOnce 不推进游标。删除和类型替换同样检查
受保护后代。成功变更推进父目录及相关目录的刷新代次，避免在途列表撤销事件。
存储失败时保留游标，发送保守失效提示；不会在元数据确认前主动丢弃旧内容缓存。

VFS 除了保护已标脏/本地待上传节点，还按 inode 计数活动写句柄。已有远端文件在
编辑 staging 时可能尚未标脏，因此从成功写打开开始保留其原版本及父链；计数到
最后一个句柄的 close 提交结束后才释放，而不是从句柄表移除时就释放。读句柄
不承担此保护。短发布锁协调写打开的读取/登记与目录合并/delta 事务，不跨 provider
目录 IO 持锁。创建在目录查询后持锁重查父 inode，避免向已被替换的父 inode 插入。

这些规则保护本地写入，不提供远端重建或上传目标迁移。被本地写保护而跳过的
delta 可以推进游标；之后的外部现状仍由 TTL 列举及上传冲突检查处理。长期打开
但未编辑的写句柄也会延迟远端变更的本地应用。活动句柄保护是当前 VFS 实例内的
状态，不是跨独立写进程的共享锁；正常 daemon 的 journal 所有权仍是单写者边界。

## 变更通知

变更先保存在 TEMP 表中，提交后再读取。小变更按最多 128 项提供；大变更只发送
目录子树重新读取提示。挂载适配层对大变更使用全挂载缓存失效，同一时刻最多一个
遍历，遍历期间的新请求会触发后续遍历，不按文件数创建 goroutine。MCP 仍是合并的
变更提示，不是持久审计日志。通知读取失败时回退到保守的重新读取/内核失效提示。

## 验证与仍有的限制

已覆盖部分暂存不可见、完整合并、当前本地写保护、事务回滚后的树/索引/TTL、
刷新代次和目标身份改变、重复游标/名称、连接数量与关闭、超过 TEMP 缓存建议值
的暂存、生产测试进程强杀重开、1200 项分页与批量通知，以及父目录消失后的本地
文件读回。停用后代保护后，传统合并、暂存合并及 VFS 的回归均会失败。
新增目录类型/对象替换的树与索引回滚、新 inode、旧子目录刷新拒绝、替换通知的
128 项预算；delta 后代保护、快照冲突、游标重试与失败通知；活动写句柄、多句柄
关闭及 close 发布窗口回归。目录替换的 VFS 测试校验旧路径失效和新对象内容读回。

下列事项不能据这些测试标为完成：

- **部分入口仍全量返回**：SFTP 已用独立 v3 读取器和专用 SSH 池接入 StreamList，
  不依赖 pkg/sftp 的完整 ReadDir/ReadDirContext。WebDAV 与 SFTP 的 List 兼容
  接口仍累计完整切片，SFTP 递归删除仍使用 ReadDir，WebDAV Stat 的 Depth:0 XML
  路径仍整体解码；VFS 冷目录使用 ListStream。仅注入 pkg/sftp Client 的测试模式
  不宣告流式能力。SFTP 的连接预算、取消、回环 SSH/VFS 验证及剩余兼容性限制见
  [SFTP 目录流边界](sftp-directory-stream.md)。
- **围栏分硬软两种**（2026-09-06）：`directory_refresh_generation` 现在有两个计数器。
  - **硬围栏 `generation`**：目录下有名字被删除或移动、或目录对象本身被替换。更早开始的
    远端快照里还有那个名字，发布它等于把刚删掉的东西复活，所以**必须拒绝**
    （`ErrListingChanged`）。`Remove` / `Rename` / delta 的删除与目录替换走这条。
  - **软围栏 `stale_generation`**：只是"这个目录过期了"——delta 提到一个我们从没列举过的
    条目，或者上传落地时后端没有描述结果。**没有任何名字被移除**，所以在途的快照仍然是
    一份真实的列举。现在的做法是**照常发布，但把 `dir_state.complete` 留在 0**，
    下一次读会重新去后端拿。`Store.Invalidate` / `InvalidateAll` 走这条。

  两者原先是同一个计数器，代价是可测量的：1000 部影片的媒体库扫描撞上变更流的首批积压时，
  列举被成批拒绝，读者拿到的是"这个目录读不了"，而那个目录其实好好的。拆开之后同一个
  压力复现里被拒次数 **72 → 8（加重试）→ 0**。回归：
  `internal/meta/listing_fence_test.go` 的
  `TestDirListingPublishesThroughAStaleMarkButStaysIncomplete`（把 `Invalidate` 改回硬围栏
  即失败）与 `internal/vfs/refresh_listing_race_test.go`（1ms 轮询风暴下断言零拒绝且绝不答错）。

  调用方的退避重试保留（5 次、约 0.25 秒上限），现在只服务硬围栏。

- **仍未做：远端内容变更仍走硬围栏**。`ApplyRemoteNode` 在 `next != nil` 的纯属性更新
  （同一父目录、同一名字、不是目录替换）上也推硬围栏，于是一次远端改文件会拒掉并发的
  父目录列举——而父目录的名字集合根本没变。改成软围栏是对的方向，但那样一来"列举不会
  覆盖 delta 刚写的属性"就从 meta 自身的保证退化为**依赖调用方传入的 `protect` 谓词**
  （VFS 传了，`protect == nil` 的调用方没有）。要么把"不覆盖列举开始之后更新过的子项"
  提升为 meta 层的无条件不变量，要么保持现状。前者会改变一批现有列举语义，**没有真实
  网盘验证不动**。生产轮询间隔 60 秒，撞上的窗口本来就窄。

- **保护窗口是秒级的**：过期列表保护比较条目的 `fetched_at` 与本次列举的开始时刻，
  而这两个时间戳是秒分辨率。于是一个刚刚被列举过的子目录，在同一秒内发起的父目录
  刷新中会被保留，即使远端已经把它删了——最多晚一秒才消失。这个方向是刻意的
  （宁可留着也不要误删），但它是一个真实的可观察行为：`test/e2e` 的 STRM 修剪回归
  必须等过这一秒才能看到删除。

- **不是硬配额**：SQLite cache_size 是建议值，TEMP 使用 SQLite/系统选择的临时
  存储位置，不计入 CloudFS 的缓存预算；临时目录可能位于 tmpfs。它需要额外的
  临时空间、WAL 和磁盘 IO，不能承诺进程总内存始终小于某个固定字节数。
- **大事务和其他全量入口**：最终原子合并仍会持有元数据写锁；超大目录的写入
  延迟、实际峰值内存与磁盘使用还需测量。普通完整 ReadDir、递归 warm、内核树
  缓存遍历和旧 PutDir 的完整输入/返回结构仍可能随目录大小增长。
  传统 PutDir 的合并会使在途暂存失效，但其接口没有“开始采集时的代次”参数，
  不提供从外部采集开始的快照校验；实际 VFS provider 列举使用 DirListing。
- 工具 total 的独立计数、旧数字游标的大偏移扫描，以及跨请求目录快照仍未优化。
- provider 分页不是跨客户端一致性快照；直接父目录的代次不能推广成任意祖先
  快照与所有并发后代操作之间的全树序列化。普通文件到普通文件的远端 ID 替换
  仍沿用原 inode 策略；本批新 inode 规则针对目录对象及文件/目录类型转换。
- 真实网盘、实际 FUSE 内核通知、物理掉电、长时间磁盘故障和长期性能尚未验收。
