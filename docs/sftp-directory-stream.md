# SFTP 流式目录枚举：生产接线与验证边界

## 当前状态

独立 SFTP v3 目录读取器已接入生产 `Provider.ListStream`、专用 SSH 连接池、
计数包装和 VFS TEMP 收集器，生产 `Caps.StreamList` 为 true。兼容 `List` 调用
同一读取器后累计切片，仍不是有界返回接口。仅注入 pkg/sftp Client 的测试模式
没有独占 SSH 传输，不宣告流式能力，保留原 ReadDir 路径。

没有修改/复制 pkg/sftp 依赖。目录读取器仅使用公开的 FileStat 模式/时间转换及
StatusError 分类，不与 pkg/sftp 客户端共享活动协议通道。它要求调用方提供一个
独占、已认证、已启动 sftp 子系统的读写连接，并取得该流的关闭所有权。

协议依据是描述 v3 的历史工作草案
[draft-ietf-secsh-filexfer-02](https://datatracker.ietf.org/doc/html/draft-ietf-secsh-filexfer-02)，
不是将该已归档草案表述为现行 IETF RFC 标准。

## 已实现的协议路径

- INIT/VERSION 版本协商、扩展键值校验；当前只接受 v3。
- OPENDIR → 多次 READDIR → 协议 SSH_FX_EOF → CLOSE 成功确认。
- 相对根、空根、`.`、`~` 和 `~/子目录` 在同一子系统用 REALPATH `.` 取得登录
  目录后解析，不调用普通文件连接的 Getwd，不运行远端 shell。要求返回唯一、
  完整的绝对路径，拒绝截断、非法名称和错误状态。每次列举解析相对根；普通
  文件操作原有的根缓存/连接初始化路径不因此获得同等取消保证。
- 每个应答核对请求 ID 和类型；网络 EOF 不等于目录列举成功。
- 单响应最多 1 MiB，在按长度分配内存前检查。解码名称/属性时按包内剩余长度
  检查计数和字段，拒绝无进展空 NAME、越界字符串、未知属性位、超大扩展计数、
  非法名称、溢出长度和多余尾部。此预算不是整个进程内存硬配额。
- 一次只保留当前包，逐条串行调用访问者。READDIR 未给全类型/大小/修改时间时，
  用同一独占连接 STAT 补查；补查结果仍不完整则失败，不猜成零长度文件。
  补查期间可同时持有一个 NAME 包和一个 ATTRS 包，均受上述单包预算约束。
- 忽略协议的 `.` / `..` 及 CloudFS 在途上传名，沿用目录项大小/时间指纹。
  无整目录 Go 切片，不对已交付前缀重试。重复名称最终仍需由 VFS TEMP 唯一键拒绝。
- 访问者错误立即返回，关闭独占流；取消通过关闭流中断阻塞 IO。正常完成需要
  CLOSE 应答成功，失败不会被确认成完整目录。异常时通过关闭子系统流释放句柄，
  不以不可取消的后台 CLOSE 请求拖住退出。底层 Close 必须线程安全并能解除阻塞。

## 验证范围

已与 pkg/sftp 的真实协议服务端经 net.Pipe 交互，验证 513 个文件、一个子目录及
隐藏的在途上传文件。另有回环 TCP 真实 SSH 服务端测试，包含加密、密码认证、
known_hosts/HostKeyAlias 和子系统协商，再运行 pkg/sftp 服务端验证相同目录。
这些是本地隔离测试，不是公网、OpenSSH/NAS 产品或真实账号验收。

专项覆盖请求 ID 错配、错误版本/状态、报文计数/长度/属性畸形、非 UTF-8/越界
名称、包尾垃圾、关闭失败、部分内容后连接 EOF、属性补查和访问者中止。
取消测试分别阻塞 INIT、OPENDIR、READDIR、STAT、CLOSE，检查取消能结束双方等待。
字段解码另有模糊测试；测试结果与执行次数见 IMPLEMENTATION 对应批次。

## 生产连接与生命周期

- `connections` 继续控制普通文件连接，默认 2；新增 `directory_connections`
  控制**额外的专用目录连接**，0/未设置取 2，允许 1～32，负数或超限拒绝。
  因而默认每 remote 最多 4 条 SSH 连接，Caps.MaxConnsPerHost 按两者之和声明。
  两个池均按需连接；若服务端账号限制会话数，可分别设为 1（合计最多 2）。
- 目录连接复用已认证的 SSH 传输，每次租约打开一个新的 sftp 子系统；不按目录
  重做握手，不与普通文件句柄共用传输。继承原 Dial（含代理路由）、认证方式、
  主机密钥/别名/算法协商及元数据限流配置，主机校验失败按认证错误拒绝。
- 排队和限流等待均可由调用方或 Provider.Close 中断。曾发现限流在池外等待时
  关闭无法唤醒的漏洞，专项先复现再修复。关闭后到达的拨号结果立即关闭，不重新
  发布连接。自定义 Dial 必须遵守 context；无法强行结束不合作的调用方函数。
- 拨号、SSH 握手、通道及子系统建立共享 15 秒设置期限；设置结束后撤销此计时，
  不把 15 秒作为整个超大目录的期限。列举由调用方 context 控制，取消关闭专用
  TCP；真实 agent/硬件签名等外部认证回调的阻塞行为仍需独立验收。
- 子系统 stderr 与服务端请求均有专用读取循环，避免流控阻塞。关闭发送及等待
  对端释放受 2 秒期限约束，失联时关闭 TCP 并等待读取循环退出，不逐次泄漏。
  旧 context 的取消回调退出后才归还租约；调用方 visitor 本身必须配合返回。
- 空闲连接已断开时，仅在打开通道失败、尚未初始化协议前允许一次重连；协议开始
  后不重放。专用池没有额外 keepalive worker，静默黑洞由设置期限/调用方期限处理；
  普通文件连接的 keepalive 不变。关闭子系统失败后连接可在下一次列举重建。

新增回归覆盖十个取消阶段、元数据限流、2 个槽位与多等待者、连续 50 次旧取消
不影响新租约、迟到拨号、认证/主机密钥拒绝、空闲重连、设置超时与长扫描、无响应
对端关闭、访问者错误身份及部分内容后不重放。已有普通读句柄在取消列举前/中/后
都读回一致，句柄打开/关闭计数不变。VFS 集成通过计数包装使用流式能力，500 项
首次完整发布后，下一次交付 300 个不同条目再断线，旧树与 TTL 均不改变。

## 本地基准与剩余限制

`BenchmarkDirectorySSHEnumeration` 用已热身的加密回环 SSH，服务端每包生成
100 项，不预建整目录。2026-09-05，macOS arm64 / Apple M5 Pro，`-benchtime=1x
-count=3`：十万项流式中位耗时 76.4 ms、累计分配约 87.2 MB；兼容 List 中位
78.8 ms、累计分配约 141.5 MB。服务端生成与两端加密分配都计入，3 次观测均复用
一条 SSH 连接。这不是峰值内存、真实目录文件 IO、WAN/NAS 吞吐或稳定性能门禁。

完整 List、递归删除、普通文件根路径解析、TEMP 空间配额、最终大事务锁延迟、
真实服务器兼容性和实际峰值内存仍需按各自范围验收。不能把这次接线或累计分配
基准当作整个进程、递归遍历或内核目录缓存的硬内存上限证明。
