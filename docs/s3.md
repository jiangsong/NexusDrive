# S3 驱动

CloudFS 的 `s3` provider 使用官方维护的 MinIO Go SDK v7 对接 AWS S3 和兼容服务。SDK
负责 SigV4、streaming payload 与预签名；所有实际 HTTP 请求仍通过 CloudFS 的原始响应
transport，因此沿用代理路由、按 remote/account/class 的限流和熔断。SDK 自动重试关闭，
流式请求的重试由上层 journal 策略统一负责。

## 配置

```yaml
remotes:
  archive:
    type: s3
    endpoint: https://s3.example.com
    region: us-east-1
    bucket: backups
    prefix: cloudfs          # 可选；所有操作被限制在此前缀
    lookup: path             # auto | path | dns
    access_key_id: ACCESS_KEY
    secret_access_key: secretfile:archive/secret_access_key
    # session_token: secretfile:archive/session_token
    # part_size: 8MiB
```

密钥可从 stdin 安全导入：

```sh
printf '%s\n' 'secret_access_key: "..."' | \
  cloudfs config auth archive --stdin --no-check
```

`endpoint` 必须是无 path/userinfo/query 的 HTTP(S) origin。生产凭据不应通过明文 HTTP；
只有本机测试服务或受保护内网才应使用 `http://`。匿名公共 bucket 可设 `anonymous: true`，
且不能同时配置任何凭据。`lookup: path` 适合多数自建兼容服务；AWS 通常可用 `auto`。

## 语义

- ID 是 prefix 内以 `/` 开头的规范 key；反斜杠、NUL、控制字符、点段和重复分隔符拒绝。
- ListObjectsV2 delimiter 结果逐条进入 VFS TEMP listing；完整结束前不会替换可见目录。
- ETag 用作条件 Range 和版本指纹。只有恰为 32 位十六进制、非 multipart 的 ETag 才标为
  MD5；加密/兼容服务或 multipart ETag 不冒充内容 MD5。
- 64 MiB 及以下走单 PUT；更大文件默认 8 MiB multipart，upload ID 和 part ETag 可跨重启
  恢复。S3 lifecycle 应配置清理长期未完成的 multipart session。
- `DownloadURL` 返回 15 分钟预签名链接。secret key 不进入 URL、YAML 日志或错误文本。
- 删除 provider 根永远拒绝；递归目录移动/删除最多一百万对象。

S3 没有目录和原子 rename。目录是 `/` delimiter 与可选零字节 marker 的投影；移动/改名
先逐对象服务端复制，全部成功后再删源。复制阶段失败会尽力回滚新对象，源数据保持；删除
阶段失败可能留下源/目标重复项。版本化 bucket 的 delete marker、外部并发写入、Object Lock
和跨 bucket copy 尚未形成更强事务契约。

## 已验证与未验证

本地状态化 HTTP 回放会校验 SigV4 Authorization，解码 AWS streaming chunks，并覆盖
delimiter 列举、HEAD/ETag、Range/If-Match、预签名、单 PUT、持久 session multipart、
Copy/Rename/Move、递归目录移动/删除、错误分类和 VFS 冷读。真实 AWS S3、MinIO、Cloudflare
R2、Backblaze B2、阿里 OSS 等仍需账号环境验收；模拟测试不替代这些结果。
